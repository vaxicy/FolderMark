## 失效书签检测改为后台运行（关闭弹窗不中断）
- 根因：原 `scanBrokenBookmarks()` 在 popup.js 内用 `fetch()` 逐个检测，关闭弹窗即中断。
- 方案：检测逻辑迁移到 `background.js`（Service Worker，已改为 ES module + `type: "module"`），
  通过 `chrome.runtime.sendMessage` 三消息协作：`start-broken-scan` / `get-broken-scan-state` / `cancel-broken-scan`。
- background 把进度/结果写入 `chrome.storage.local`（key `brokenScanState`：`{status,completed,total,broken,validCount,error,...}`），进度写入节流 >300ms。
- popup 改为发消息 + 每 400ms 轮询 storage 更新进度条；`init()` 末尾 `restoreBrokenScanState()`：进行中则继续轮询，已完成则直接渲染上次结果。
- 权限请求（用户手势）仍留在 popup，授权后才通知 background 开始。

## favicon fallback 修复（显示 x 问题）
- 原因：`bindFaviconFallbacks` 只用 `addEventListener('error', ...)`，但 img 设置 src 到事件绑定之间有异步窗口——已加载失败的图片会错过 error 事件，浏览器显示破损图标「x」。
- 修复：绑定前先检查 `if (img.complete && img.naturalHeight === 0)`（图片已完成加载且高度为0=已失败），直接替换为 🔗 文本。正常情况仍走 error 事件兜底。
